# 如何让 Divergence 保留更多可能性

调研日期：2026-11-23。目标不是无限随机，而是为同一个真实问题提供机制不同、尊重约束、能验证的多个方向。

## 研究依据

### 1. 单个回答更丰富，不等于整体更有差异

Anderson、Shah 与 Kreminski 的 C&C 2024 研究包含36名参与者：在其研究任务中，ChatGPT 辅助的点子更详细、数量更多，但参与者之间的想法也更趋同。这提示我们应关注不同机制与用户能动性，不能只统计卡片数量。

来源：[Homogenization Effects of Large Language Models on Human Creative Ideation](https://arxiv.org/abs/2402.01536)。局限：特定任务和样本，不能直接证明所有模型/任务同样表现。

**实现推论**：深度模式的三个分支使用相同用户简报、不同视角，生成阶段互不看对方输出。直到重组阶段才共享候选。它是减少锚定的工程假设，不是该论文验证过的具体算法。

### 2. 提示模型考虑候选分布

Zhang 等人的 Verbalized Sampling 研究提出让模型同时生成候选及其概率描述，以缓解对典型答案的偏好；论文报告在若干创作和开放任务中改善输出多样性。研究结果不能直接外推为本应用的效果保证。

来源：[Verbalized Sampling: How to Mitigate Mode Collapse and Unlock LLM Diversity](https://arxiv.org/abs/2510.01171)。

**实现**：系统提示允许候选携带主观 probability，并要求非典型方向。本产品使用的是受 VS 启发的提示变体，不严格复现论文采样流程，不根据模型自报概率随机抽取答案。自报概率不是真实统计、质量评分或新颖性评分，界面不将其作为分数展示。

### 3. 多样性包含探索路径和时序

2026年的研究讨论了早期候选带来的固着，以及不同个体之间的多样性问题，说明只提高温度可能不足。

来源：[Examining and Addressing Barriers to Diversity in LLM-Generated Ideas](https://arxiv.org/abs/2602.20408)。

**实现推论**：显式区分“生成候选”与“检验可行性”，保留跨界组合前的分支；用户可以沿某条继续，也可以主动避开此前机制。系统不会自动投票或删掉少数方向。

## 可行方法与取舍

| 方法 | 当前实现 | 收益假设 | 局限/成本 |
| --- | --- | --- | --- |
| 独立视角生成 | 人的需求 / 反转常识 / 跨界借用三个并行请求 | 避免候选相互锚定 | 同一模型仍可能产生相似内容；三次调用 |
| 约束反转、远领域类比 | 在分支指令中明确机制 | 减少只换名字的常见清单 | 类比可能牵强，需要最小验证 |
| 候选分布提示 | 鼓励非典型候选与可选主观概率 | 缓解典型回答倾向 | 非完整 VS 复现，概率不可校准 |
| 跨方向重组 | 第四次请求追加1–2个新组合 | 产生组合式新意 | 可能重复，原始分支保持可见 |
| 引导问答 | 用户开启后只问1–3个问题 | 与真实处境对齐 | 多一轮交互；不强制每次问问题 |
| 可控采样温度 | 默认1.1，可调或关闭参数 | 保留一些随机探索 | 高温不等于好创意，部分模型不支持 |
| 检索与知识注入 | SKILL.md + 用户接入 MCP | 接触新材料、验证约束 | 没有搜索插件就不能声称实时调研 |
| 保留人类选择 | 多方向、收藏、点子分支 | 允许非主流点子继续生长 | 需要用户判断，没有“最优答案”保证 |

不默认实现复杂多 Agent 投票、反复自我评分或无限反思：这些做法增加成本，也可能提前淘汰异质点子。本版的“独立视角”是同一后端编排的独立模型请求，并非运行多个自治 Agent。

## 从创意到能落地的建议

每个方向要求：具体机制、与处境的关系、行动步骤、最小实验、成本或失败条件。关系类关注真诚与同意；管理类先考虑自主性、公平和负荷；创业类明确用户和验证路径；网站类给出独立 HTML 原型而非只列风格词。

这保留了对现实约束的检查，不把可行性检查变成只能剩一个候选的排序器。不会通过取消事实边界或安全边界来制造所谓创造力。

## 评估方案与当前证据

当前自动化验证的是工程行为，不是创意质量：独立分支的上下文隔离、部分失败保留、JSON 修复、取消、API 契约、MCP 授权、存储及桌面交互。

后续应将四类用户示例扩展为至少40条带约束任务，同一模型比较直接“给我一些想法”、快速发散、深度探索三组，记录实际 token、延迟、调用失败率。让不知道来源的至少两名评审分别评估：

1. **新颖性**：机制是否少见，而非只是起新名字。
2. **多样性**：同一组内是否覆盖不同机制与用户场景。
3. **贴合与可执行性**：是否遵守预算、规则、关系边界，第一步能否落实。
4. **用户能动性**：用户能否改写、组合、拒绝；是否感觉被单一答案牵引。

语义嵌入距离只能作为多样性的辅助信号；不能当成创造力的客观总分。应同时统计重复机制、违反约束和伪造来源，不只看平均分。未完成上述评估前，不宣称创造力提高某个百分比。
